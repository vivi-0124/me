# Orca まとめ：AI エージェントを並列で回す ADE

Zenn と Qiita の Orca 記事（2026年4月〜10月、約40本）を読んで、1本にまとめた。2026-10-18 時点。
Orca は毎日のように更新されるので、細かい設定名や画面は変わっている可能性がある。

## 3行で

- Orca は、Claude Code や Codex などの CLI エージェントを **タスクごとの git worktree で並列に動かす** デスクトップアプリ。自称 ADE（Agent Development Environment）
- worktree 作成 → エージェント起動 → 差分レビュー → コミット / PR までが1つの画面で終わる。内蔵ブラウザとモバイルアプリの評価が特に高い
- 注意点は3つ。Yolo モードが既定でオン、SSH 接続先から手元の Orca を操作できてしまう、更新が速すぎてドキュメントと画面がずれる

## Orca とは

- 開発元は Stably.ai（Y Combinator 出資）。リポジトリは [stablyai/orca](https://github.com/stablyai/orca)、公式サイトは [onorca.dev](https://www.onorca.dev/)
- MIT ライセンスの OSS で無料。macOS / Windows / Linux 対応。iOS / Android のモバイルアプリもある
- モデルは同梱しない。手元の Claude Code・Codex・Cursor CLI・Gemini・OpenCode・Copilot など（40以上）を、**自分のサブスクのまま** 起動する
- GitHub スターは 2026年6月に約8,000、10月初めに約84,000。急に伸びた
- 同じ名前の別物が多い（OrcaRouter、量子化学の ORCA、レセコンの ORCA など）。検索するときは「onorca」で探すと確実

### IDE と何が違うか

IDE は人がコードを書くための道具。ADE は **複数のエージェントに書かせて、人は比較・レビュー・マージに回る** ための道具。公式のキャッチコピーは「Fan one prompt across 5 agents, compare, merge the winner.」

ファイル編集の機能は最低限なので、「セッションを4つ以上同時に扱うなら Agent IDE のほうがいい」という意見もあった（rhosokawa さん）。

## 導入

```sh
brew install --cask stablyai/orca/orca
```

- `brew install --cask orca` だと **別のツールが入る**。必ずフルパスで指定する
- 初回起動時に macOS が Codex をマルウェア判定してゴミ箱へ移すことがある。原因は Codex 側の既知の誤検知で、Orca が CLI を検出するときに触れて XProtect が反応する。消えたら Codex を最新版で入れ直す
- オンボーディングで既定のエージェントを選ぶ。**Yolo モードは既定でオン**（確認なしでコマンド実行・ファイル編集）。業務リポジトリならここで判断する
- 設定で Orca CLI を有効にしておくと、エージェントに「このワークスペースを In review にして」のように Orca の操作を頼める

## 基本の使い方

Orca では「worktree とそこで動くエージェントのセット」を **ワークスペース** と呼ぶ。

1. 「プロジェクトを追加」でリポジトリを登録する（サイドバーに「プライマリ」として出る）
2. `+`（⌘N）でワークスペースを作る。タスク名とエージェントを選ぶだけ。GitHub Issue 番号や Jira の URL も入れられる
3. エージェントが worktree の中で作業する。左のサイドバーで、どれが作業中・入力待ち・完了かが一覧できる
4. 差分ビューでレビューし、コミット・PR 作成まで Orca 内で行う

worktree ごとにターミナル・ブラウザタブ・差分のレイアウトを持つので、worktree を切り替えると画面が丸ごと切り替わる。「タスクごとに机を増やす感覚」（kozoka_ai さん）。

### .env などを新しい worktree に持ち込む

git worktree には `.gitignore` 対象のファイルが入らない。方法は2つ。

- **`.worktreeinclude`**：書いたファイルをプライマリからコピーする（glob 不可）
- **`orca.yaml` の `scripts.setup`**：worktree 作成直後にコマンドを実行する。環境変数 `ORCA_ROOT_PATH`（元リポジトリ）と `ORCA_WORKTREE_PATH`（新 worktree）が渡される

```yaml
scripts:
  setup: |
    cp "$ORCA_ROOT_PATH/.env" "$ORCA_WORKTREE_PATH/.env"
    npm ci
setupAgentStartupPolicy: wait-for-setup   # トップレベルに書く。scripts の下だと黙って無視される
```

`wait-for-setup` がないと、インストール中にエージェントがテストを走らせて失敗することがある。

## 評価が高い機能

| 機能 | 内容 |
|---|---|
| 内蔵ブラウザ | Chromium ベース。複数タブ・パスキーが使え、worktree を切り替えるとタブ群も一緒に切り替わる。「Agent IDE の中で1, 2を争う」（rhosokawa さん） |
| Design Mode | ブラウザ上の要素をクリックすると、HTML・計算済み CSS・切り抜きスクリーンショットがプロンプトに添付される。複数コメントをまとめて送れる。ソースマップがあればファイルと行番号まで特定する |
| 差分へのコメント | 差分の行の `+` から Markdown でメモを付け、「Send to agent」でまとめて送る。PR を出す前に手元でレビューが終わる |
| セッションの永続化 | Mac を再起動しても前日のセッションがサイドバーに残る。中ではカードごとに `claude --resume <ID>` を打ち直している |
| 細かい気配り | default branch の自動同期、Claude / Codex の使用量をフッターに表示、worktree ごとのディスク・メモリ表示、AI が作った子 worktree の非表示 |

## Orca CLI とオーケストレーション

Orca の一番の特徴は「人がエージェントを監督する」だけでなく、**エージェント自身が CLI で Orca を操作できる** こと。worktree 作成、ターミナルへの入力、ブラウザ操作（`snapshot` / `click` / `fill`）、iOS Simulator、computer use、cron 実行（automation）までできる。

エージェント同士のやり取りには2つの方法がある。

| | `terminal send` / `read` | `orchestration` |
|---|---|---|
| 仕組み | 相手のターミナルに直接入力し、画面を読む | Orca の受信箱を介して送受信 |
| 返答の区切り | 画面から推測する | `worker_done` で明示的に届く |
| 向いている用途 | 短い議論・雑談 | 実装・レビューの分担、完了報告が要る作業 |

使い方は `orca skills get orchestration` で読める。エージェントに「Codex にレビューを頼んで」と言えば、これを読んで自分で進めてくれる。

### orchestration でハマる点

- `orca orchestration run` は **run ID と器を作るだけ**。Issue を解釈してタスクを配る役は自動では生まれない。コーディネータ役のエージェントを別に立て、`task-create` と `dispatch --inject` をさせる必要がある
- `dispatch --inject` は、担当の役割・コーディネータの handle・task ID・完了報告コマンドをワーカーに自動で注入する
- レビュー指摘を **元の担当ワーカーに差し戻せる** ので、実装 → レビュー → 修正 → 再レビュー → マージまで一周できる
- `gate-create` で「人が選ぶまで止める」判断ゲートを作れる

構成例：Claude Code をコーディネータとワーカーに、Codex を読み取り専用（`--sandbox read-only`）のレビュー役にする。

## リモート・モバイル

- **Orca Mobile**：デスクトップで出したペアリングコード / QR を読むと、スマホからワークスペースの状態確認、ターミナル閲覧、エージェントへの返信、ファイル編集、差分・PR の確認ができる。完了時にプッシュ通知が来る。UI がデスクトップとほぼ同じなのが評価されている
- **LAN の外から使う**：接続方式は Orca Relay（要サインイン）か直接接続。リレーを使いたくない場合は Tailscale やロリポップ！ゼロトラストリンクのメッシュ IP を接続先に選べばよい。蓋を閉じて出かけるならスリープ無効化も要る
- **SSH**：接続先に Orca relay（Node.js 製）が自動で置かれ、worktree・ターミナル・git は接続先で動き、エディタと差分は手元に残る
- **Windows + WSL**：SSH は不要。エージェントのランタイムを WSL にし、プロジェクトのパスに `\\wsl.localhost\Ubuntu\home\...` の UNC パスを指定するだけで開ける

## プラグイン（試験的）

- v1.4.162 でプラグインとマーケットプレイスが追加された。マーケットプレイスの実体は「各プラグインの取得先を並べた Git リポジトリ」
- 自作はフォルダ1つに `orca-plugin.json` と HTML などを置けば動く。ビルド不要
- マニフェストのハマりどころ
  - `id` を `orca-` で始めるとインストールを拒否される（エラー文に理由が出ない）
  - `engines.orca` は `>=x.y.z` 形式のみ。`^1.4.0` は弾かれる
  - `contributes` は panels / commands / events / keybindings / languagePacks / vmRecipes など決まったキーだけ。余計なキーがあるとマニフェスト全体が無効になる

## 他のツールとの比較

| ツール | 立ち位置 | 向いている人 |
|---|---|---|
| Ghostty | 純粋なターミナル | 環境を自分で組みたい人 |
| cmux | Ghostty ベースのエージェント向けターミナル（macOS のみ） | ターミナルで生活していて、入力待ちの通知だけ欲しい人 |
| **Orca** | worktree・ブラウザ・レビューまで一体の ADE | GUI で worktree と差分を管理したい人 |
| Warp | OS をまたぐ開発環境 | 複数 OS で環境を揃えたい人 |
| Herdr | 描画しないエージェントランタイム | 今のターミナルに管理と永続化だけ足したい人 |

乗り換え元は Ghostty・iTerm2・cmux・Superset・VS Code が多い。「cmux + Yazi + difit + 手作業の worktree 管理」が Orca 1つで済んだ、という声もある（appleworld さん）。

## 注意点・ハマりどころ

1. **Yolo モードが既定でオン**。エージェントに広い権限を渡している自覚を持つ
2. **SSH 接続先から手元の Orca を操作できる**。接続先に置かれる `~/.orca-relay/bin/orca` 経由で、接続先の一般ユーザー（＝そこで動くエージェント）が、手元のローカルターミナルに入力を送れることが報告されている（Orca 1.4.210 で検証）。コンテナでサンドボックス化していても、この経路は塞げない
3. **ドキュメントと画面がずれる**。「デスクトップを閉じると切れる、クラウドリレーはない」と書いてあっても、実際の既定値は「リレー + ローカル」だった例がある
4. **git 管理されていない親ディレクトリ（ポリリポ構成）では worktree を作れない**。Folder モードではワークスペースが1つしか開けない。シンボリックリンクで回避した例がある
5. **zsh の履歴が `claude '--resume' '<ID>'` で埋まる**。`zshaddhistory` フックでクォート付きの行だけ除外すれば直る
