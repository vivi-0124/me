# ポート番号とは？IPアドレス・ドメイン名との関係から開発での注意点まで

## はじめに

開発サーバーを立ち上げると `http://localhost:5173` のようなURLが表示されます。この `:5173` がポート番号です。
普段なんとなく使っていますが、「なぜHTTPSのサイトは全部443番なのに区別できるのか？」「なぜ開発サーバーは番号を分ける必要があるのか？」を整理してみました。

## 前提：TCP/IPをざっくり

インターネットの通信は、役割の違う複数の仕組み（層）を重ねて動いています。これをまとめて **TCP/IP** と呼びます。

| 層 | 代表例 | 役割 |
| --- | --- | --- |
| アプリケーション層 | HTTP, HTTPS, SSH, DNS | 何をやり取りするか（Webページ、コマンドなど） |
| トランスポート層 | TCP, UDP | どのプログラムに届けるか（**ポート番号**） |
| インターネット層 | IP | どのコンピュータに届けるか（**IPアドレス**） |
| リンク層 | Ethernet, Wi-Fi | 隣の機器まで実際に信号を送る |

荷物の配送に例えると、こうなります。

- **IP** は、荷物を宛先の**建物**まで運ぶ係。IPアドレスだけを見て運ぶ
- **TCP / UDP** は、建物に着いた荷物を**部屋**（プログラム）に配る係。ポート番号を見て配る
- **HTTP** などは、荷物の**中身**の書き方の決まり

TCPとUDPの違いは次のとおりです。

- **TCP**: 届いたか確認し、順番どおりに並べ直す。確実だが手間が多い（Web、SSH、DBなど）
- **UDP**: 送りっぱなし。速いが、欠けても気にしない（DNS、動画通話、ゲームなど）

### ドメイン名はどこに出てくるか

IPが見るのはIPアドレスだけで、`example.com` のような**ドメイン名は知りません**。

ブラウザは通信を始める前に、**DNS**で「`example.com` のIPアドレスは何か」を調べ、その結果のIPアドレスに接続します。ドメイン名は人間が覚えやすくするための名前で、通信そのものはIPアドレスとポート番号で行われています。

ここまでを踏まえると、次の疑問が出てきます。

- IPアドレスとポート番号で宛先が決まるなら、同じ443番を使うHTTPSのサイト同士はどう区別しているのか？
- 1台のPC（同じIPアドレス）で複数のプログラムを動かすと、何が起きるのか？

以下で順番に見ていきます。

## ポート番号とは

ポート番号は、1台のコンピュータ（IPアドレス）上で**どのプログラム宛ての通信か**を区別するための番号です。

- IPアドレス = 建物の住所
- ポート番号 = 部屋番号

というイメージです。通信の宛先は `IPアドレス:ポート` の組で指定します（例: `192.168.1.10:8080`）。

### 基本仕様

- 範囲は **0〜65535**（16ビット）
- **TCPとUDPで別々に**存在する

### 番号の区分

| 範囲 | 名称 | 用途 |
| --- | --- | --- |
| 0〜1023 | ウェルノウンポート | 標準サービス用。Linuxなどでは使用にroot権限が必要 |
| 1024〜49151 | 登録済みポート | 特定アプリ向けにIANAが登録 |
| 49152〜65535 | 動的・プライベートポート | クライアントが一時的に使う（エフェメラルポート） |

### よく見るポート番号

| ポート | 用途 |
| --- | --- |
| 22 | SSH |
| 53 | DNS |
| 80 / 443 | HTTP / HTTPS |
| 3306 | MySQL |
| 5432 | PostgreSQL |
| 6379 | Redis |
| 3000 / 5173 / 8080 | 開発サーバーでよく使われる（5173はVite） |

## HTTPSのサイトはなぜ全部443番で区別できるのか

HTTPSのサイトは、基本的にどれも443番を使っています。それでも区別できるのは、まず**IPアドレスが違う**からです。

ただし実際には、**多くのサイトが同じIPアドレスを共有しています**。レンタルサーバー、CDN（Cloudflareなど）、クラウドのロードバランサーでは、1つのIPの443番で多数のサイトを受けることも珍しくありません。

この場合は、IPではなく**ドメイン名**で区別しています。

- **SNI**: HTTPS接続の開始時に、ブラウザが「`example.com` に繋ぎたい」とドメイン名を伝える仕組み
- **Hostヘッダー**: HTTPリクエストの中に書かれるドメイン名

### バーチャルホスト

1つのサーバーで複数のサイトをドメイン名ごとに振り分ける仕組みを**バーチャルホスト**と呼びます。nginxの設定例はこんな感じです。

```nginx
server {
    listen 443 ssl;
    server_name example.com;
    root /var/www/example;
}

server {
    listen 443 ssl;
    server_name blog.example.com;
    location / {
        proxy_pass http://127.0.0.1:3000;
    }
}
```

### 通信が届くまでの流れ

1. **IPアドレス** → どのサーバー（マシン）か
2. **ポート番号** → そのサーバー上のどのプログラム（nginxなど）か
3. **ドメイン名（SNI / Host）** → そのプログラムの中でどのサイトとして応答するか

## 開発サーバーはなぜポートを分けるのか

ローカル開発では、フロントエンドもAPIもDBも**同じマシン（localhost）**で動きます。IPアドレスが同じなので、**同じポートで複数のプログラムが待ち受けることはできません**。

そのため、

- フロントエンド: `localhost:5173`
- API: `localhost:3000`
- DB: `localhost:5432`

のように番号を分けて使います。

なお、nginxなどのリバースプロキシを前に置けば、`app.localhost` と `api.localhost` を同じ80番のままドメイン名で振り分けることもできます。

## 開発で知っておくと役立つこと

### localhost と 0.0.0.0 の違い

- `127.0.0.1`（localhost）で待ち受け → **自分のPCからのみ**接続できる
- `0.0.0.0` で待ち受け → **同じネットワークの他の端末**（スマホなど）からも接続できる

Viteなら `--host` オプションで切り替えられます。

```bash
npx vite --host
```

### 「address already in use」エラー

そのポートを別のプロセスが使用中という意味です。使用中のプロセスは以下で確認できます。

```bash
# Mac / Linux
lsof -i :3000

# Windows
netstat -ano | findstr :3000
```

### ポートフォワーディング

Dockerやkubectlのポート指定は「ローカル側:転送先」の形です。

```bash
# ホストの8080 → コンテナの80
docker run -p 8080:80 nginx

# ローカルの8080 → クラスタ内サービスの80
kubectl port-forward svc/app 8080:80
```

`svc/app` は「どこへ転送するか」を `種類/名前` の形で指定する部分です。

- `svc` … Kubernetes の **Service**（`service` の省略形）。複数の Pod をまとめて1つの宛先として見せるリソース
- `app` … その Service の**名前**（`kubectl get svc` で一覧が見られる）

つまり「`app` という名前の Service の80番」へ転送する、という意味です。末尾の `80` は Service 側のポート番号で、コンテナ自体のポートとは限りません。

種類の部分を変えると、転送先を変えられます。

```bash
kubectl port-forward pod/app-7d9f8-abcde 8080:80   # 特定の Pod
kubectl port-forward deployment/app 8080:80        # Deployment 配下の Pod
kubectl port-forward svc/app 8080:80 -n staging    # 別の namespace の Service
```

Service を指定しても、実際には裏にある Pod のどれか1つに繋がります。リクエストが複数の Pod に振り分けられるわけではない点に注意してください。

### URLでポートを省略できる理由

`https://` なら443、`http://` なら80が既定値なので、省略しているだけです。既定値以外のポートは `http://localhost:5173` のように明記する必要があります。

### クライアント側もポートを使っている

ブラウザも接続ごとに一時的なポート（エフェメラルポート）を割り当てています。通信は

```
送信元IP:送信元ポート ↔ 宛先IP:宛先ポート
```

の組で区別されるので、同じサイトを複数タブで開いても通信が混ざりません。

### ポートを開ける＝外部に公開する可能性

本番サーバーでは、ファイアウォールやセキュリティグループで「どのポートを外部に開けるか」を管理します。DB（3306や5432）などを外部に開けたままにするのは危険なので、必要なポートだけ開けるようにしましょう。

## まとめ

- ポート番号は、同じIPアドレス上で**どのプログラム宛てか**を区別する番号
- HTTPSのサイトは同じ443番でも、**IPアドレス**や**ドメイン名（SNI / Host）**で区別している
- 1つのサーバーで複数サイトを扱う仕組みが**バーチャルホスト**
- 開発環境は同じlocalhostなので、**ポート番号を分ける必要がある**
- `0.0.0.0` での公開範囲や、本番でのポート開放には注意する
